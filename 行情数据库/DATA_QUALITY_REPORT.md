## 二、问题详情与修复

### 问题1: PE字段错误（已修复）

**问题描述**:  
腾讯qt接口字段索引错误，使用`fields[64]`获取PE值，实际应为`fields[46]`。

**影响范围**:  
所有股票的PE数据均异常偏低（0.11-1.58），无法用于估值分析。

**修复方案**:  
修改 `fetch_all_data.py` 第69行：
```python
# 修复前
'pe': float(fields[64]) if len(fields) > 64 and fields[64] else None,

# 修复后
'pe': float(fields[46]) if len(fields) > 46 and fields[46] else None,  # PE-TTM
```

**修复后数据验证**:
| 股票 | PE(TTM) | PB | 市值(亿) |
|------|---------|-----|---------|
| 淳中科技 | 10.21 | 24.88 | 185.06 |
| 工业富联 | 7.23 | 26.69 | 12708.16 |
| 通富微电 | 5.74 | 9.24 | 967.38 |
| 环旭电子 | 2.88 | 9.09 | 644.77 |
| 胜宏科技 | 6.26 | 13.26 | 2090.31 |
| 赛腾股份 | 4.78 | 15.53 | 167.27 |
| 天孚通信 | 46.01 | 37.17 | 2868.77 |
| 长电科技 | 4.63 | 6.70 | 1340.81 |

**数据源**: 腾讯证券qt接口 (`https://qt.gtimg.cn/q=`)  
**字段定义**: [46]=PE-TTM, [65]=PB, [44]=总市值(亿)

### 问题2: 实时行情字段映射错误（已修复）

**问题描述**:  
腾讯qt接口实时行情字段映射存在多处严重错误，导致涨跌额、涨跌幅、成交额、日期全部错位：

| 脚本 | 错误字段 | 实际含义 | 应为 |
|------|----------|----------|------|
| data_source_manager.py | `change=parts[32]` | 涨跌幅% 被当涨跌额 | parts[31] 涨跌额 |
| data_source_manager.py | `pct_chg=parts[33]` | 最高价 被当涨跌幅% | parts[32] 涨跌幅% |
| data_source_manager.py | `volume=parts[6]×10000` | 成交量(手)错误放大 | parts[6] 手 |
| data_source_manager.py | `date=parts[31]` | 涨跌额 被当日期 | parts[30] 时间戳前8位 |
| dashboard_api.py | `prev_close=parts[5]` | 今开价 被当昨收 | parts[4] 昨收价 |
| dashboard_api.py | `volume=parts[6]×10000` | 同上 | parts[6] 手 |
| dashboard_api.py | `date=parts[31]` | 同上 | parts[30] |
| simple_dashboard.py | `prev_close=parts[5]` | 今开价 被当昨收 | parts[4] |
| fetch_chain_quotes.py | `amount=fields[37]` | 万元 被当元 | ×10000转元 |
| fetch_turnover.py | `amount=fields[57]` | 万元 被当元 | ×10000转元 |
| fetch_all_data.py | `营收≈万` 标注 | akshare返回元 | 标注元/亿 |

**权威字段定义**（已实测 `qt.gtimg.cn/q=sh603516` 验证）:
```
[3]当前价 [4]昨收 [5]今开 [6]成交量(手) [30]时间戳
[31]涨跌额 [32]涨跌幅% [33]最高 [34]最低 [37]成交额(万元)
[38]换手率% [44]总市值(亿) [45]流通市值(亿) [46]PE-TTM [65]PB
```

**修复后验证**（淳中科技，实测）:
| 字段 | 修复前 | 修复后 | 真实值 |
|------|--------|--------|--------|
| 涨跌额 | -2.74(实为涨跌幅) | -2.56 | -2.56 |
| 涨跌幅% | 96.16(实为最高价) | -2.74 | -2.74 |
| 成交额 | 52679(万元误当元) | 526790000元 | 526787189元 |
| 昨收基准 | 93.82(今开) | 93.60 | 93.60 |
| 日期 | -2.56(涨跌额) | 20260828 | 20260828 |

**影响范围**:  
- 涨跌额/涨跌幅完全错位，所有依赖这些字段的排序、分析、展示均错误
- 成交额缩小1万倍
- 涨跌幅基准错误导致百分比计算偏差

**修复方案**:  
按权威字段定义修正全部6个脚本，统一 amount 单位为元，统一 pct_chg 为小数格式（前端×100显示）。

**数据源**: 腾讯证券qt接口 (`https://qt.gtimg.cn/q=`)  
**验证时间**: 2026-08-29 03:49

### 问题3: 融资融券数据滞后（数据源限制）

**问题描述**:  
akshare的`stock_margin_detail_sse()`接口返回的数据停留在2023年9月22日，比实际时间落后约3年。

**影响范围**:  
融资融券明细数据无法用于当前分析。

**原因分析**:  
- akshare接口数据源可能已变更
- 或接口频率限制导致无法获取最新数据
- 上交所官网披露的两融明细数据可能存在延迟

**替代方案**:  
1. 直接使用东方财富网数据中心API
2. 或标注数据日期，仅用于历史趋势分析
3. 等待akshare更新接口

**当前处理**:  
已在数据文件中记录实际数据日期，前端展示时标注"数据可能滞后"。

**数据源**: akshare `stock_margin_detail_sse()` / `stock_margin_detail_szse()`  
**建议**: 改用东方财富API或直接爬取上交所官网数据

**数据源**: akshare `stock_hsgt_hist_em()`

## 三、数据质量保障机制

### 3.1 数据采集规范

| 数据类型 | 采集频率 | 数据源 | 校验规则 |
|----------|----------|--------|----------|
| 日K线 | 每日15:30 | 腾讯qt接口 | 数据条数≥300，日期连续 |
| 5分钟K线 | 每日15:30 | 腾讯qt接口 | 交易日覆盖≥20天 |
| PE/PB | 每日15:30 | 腾讯qt接口 | PE∈[1,100], PB∈[0.5,50] |
| 涨跌统计 | 每日15:30 | 新浪财经 | 总家数≈5000 |
| 龙虎榜 | 每日15:30 | 东方财富 | 记录数>0 |
| 北向资金 | 每日15:30 | akshare | 历史数据完整 |
| 融资融券 | 每日15:30 | akshare | 标注数据日期 |
| 限售解禁 | 每日15:30 | akshare | 记录数>0 |
| 财务指标 | 每日15:30 | akshare | ROE∈[0,50]% |

### 3.2 数据校验流程

```
数据采集 → 基础校验 → 合理性校验 → 问题记录 → 报告生成
    ↓           ↓           ↓           ↓          ↓
 腾讯/     字段完整性   PE/PB范围    标注问题   质量报告
 akshare   日期连续性   财务合理性   数据源限制  存储保存
```

### 3.3 问题数据标注规范

对于无法获取的最新数据，必须：
1. 在数据文件中记录`data_date`字段，标注实际数据日期
2. 在前端展示时添加"数据滞后"提示
3. 在诊断报告中明确说明问题原因
